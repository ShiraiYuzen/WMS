## 一、全局约定

- **baseURL**：`VITE_API_BASE_URL || '/api'`，所有路径以 `/api` 开头。
- **鉴权**：登录后把 token 存 `localStorage.wms_token`，之后每个请求带 `Authorization: Bearer <token>`。  
  服务端维护 `token → 登录人` 会话表，有效期 8 小时；无效或过期返回 **401**，前端自动清 token 跳登录页。
- **授权**：写接口按角色白名单校验，不匹配返回 **403**（权限矩阵见 [`README.md`](README.md) 4.5）。
- **统一响应体**：`{ code, message, data, timestamp }`，`code === 0` 为成功，非 0 时 `message` 可直接展示给用户。
- **分页入参**：`{ pageNum, pageSize, ...筛选 }`，`pageNum` 默认 1、`pageSize` 默认 10。
- **分页出参**：`{ records, total, pageNum, pageSize, pages }`。
- **GET 附带 `_t`**：前端会追加 `_t=<时间戳>` 防缓存，后端忽略即可。
- **时间格式**：一律 `yyyy-MM-dd HH:mm:ss` 字符串，不用时间戳。
- **字段命名**：JSON 全部 camelCase（`JdbcMaps` 自动把 `snake_case` 列名转驼峰）。
- **操作人**：写接口的操作人/拣货员/复核员**由服务端从 token 取**，请求里传同名参数不生效。

## 三、枚举字典（`GET /api/base/enums`）

后端 `Dict` 是唯一来源，前端不再硬编码中文文案。返回形如 `{ "orderStatus": [{ "code": "CREATED", "desc": "已创建" }, …] }`。

| 字典 key         | 取值（部分）                                                                                                         |
| ---------------- | -------------------------------------------------------------------------------------------------------------------- |
| `orderStatus`    | CREATED 已创建 / POOLED 已汇聚 / WAVED 已入波 / PICKED 已拣货 / REVIEWED 已复核 / OUTBOUND 已出库 / CANCELLED 已取消 |
| `waveStatus`     | CREATED / ASSIGNED / PICKING / PICKED / REVIEWING / REVIEWED / HANDOVERED / CLOSED / CANCELLED                       |
| `waveStrategy`   | BY_AREA 按区域 / BY_CARRIER 按承运商 / BY_TIMELINESS 按时效 / BY_ORDER_COUNT 按单量                                  |
| `pickTaskStatus` | WAITING 待领取 / PICKING 拣货中 / FINISHED 已完成 / EXCEPTION 有缺货 / CANCELLED 已取消                              |
| `pickItemStatus` | PENDING / PICKED / SHORTAGE / PARTIAL / SKIPPED                                                                      |
| `reviewStatus`   | WAITING / PASS / DIFF / REPICKING                                                                                    |
| `diffType`       | NONE / SHORT 少货 / OVER 多货 / WRONG_SKU 错货 / DAMAGED 破损 / WRONG_ORDER 串单                                     |
| `shortageStatus` | PENDING / HANDLED / CLOSED                                                                                           |
| `handoverStatus` | CREATED / CONFIRMED / REJECTED / CANCELLED                                                                           |
| `employeeRole`   | ADMIN 仓库主管 / WAVE_OPERATOR 波次员 / PICKER 拣货员 / REVIEWER 复核员                                              |
| `priority`       | URGENT 加急 / NORMAL 普通                                                                                            |
| `locationStatus` | ENABLED / LOCKED / FULL / DISABLED                                                                                   |

## 五、关键聚合结构

### 5.1 overview（`dashboard/summary` 与 `analytics/overview` 共用）

```json
{
  "totalOrders": 60, "pendingOrders": 12, "pooledOrders": 8,
  "totalWaves": 7, "workingWaves": 3, "finishedWaves": 4,
  "pickedQty": 1280, "outboundOrders": 42, "handedPackages": 96,
  "pickEfficiency": 186.5, "avgPickDurationSec": 1520,
  "errorRate": 0.0031, "shortageRate": 0.012, "reviewPassRate": 0.96,
  "pendingShortageCount": 2,
  "alerts": [{ "metric": "pickEfficiency", "metricName": "拣货效率",
               "currentValue": 98, "threshold": 120, "level": "WARN",
               "message": "拣货效率低于 120 件/小时" }]
}
```

预警阈值（`Stats` 里集中定义，改口径只改一处）：

| 指标                 | 阈值          | 级别   |
| -------------------- | ------------- | ------ |
| `pickEfficiency`     | < 120 件/小时 | WARN   |
| `errorRate`          | > 0.005       | DANGER |
| `shortageRate`       | > 0.02        | DANGER |
| `avgPickDurationSec` | > 3600 秒     | WARN   |

### 5.2 trend bucket

多日区间按天出点，`label` 为 `YYYY-MM-DD`：

```json
[{ "label": "2026-10-20", "waveCount": 3, "orderCount": 18, "pickedQty": 210,
   "shortageQty": 2, "errorRate": 0.0021, "avgDurationSec": 1380, "pickEfficiency": 198.4 }]
```

区间只有一天（看板的「今日」）时**按小时**出 24 个点，`label` 为 `YYYY-MM-DD HH:00`，
前端按 `label` 长度切换 X 轴格式（`2026-10-20 09:00` → `09:00`）。一天一个点画出来只有一根柱子，看不出节奏。

字段口径：

| 字段                                         | 按什么时间归集                                              |
| -------------------------------------------- | ----------------------------------------------------------- |
| `waveCount`、`orderCount`                    | 波次**创建**时间                                            |
| `pickedQty`、`pickEfficiency`、`shortageQty` | 拣货任务**完成**时间，用 `actual_qty` / `duration_sec` 实算 |
| `errorRate`                                  | 复核单**完成**时间，`DIFF` 占比                             |
| `avgDurationSec`                             | 该时段波次的平均拣货耗时                                    |

`pickEfficiency` 在当天没有耗时记录时返回 `null`（不是 0）——「无数据」和「效率归零」不是一回事，
前端用 `connectNulls` 把已知点连起来，不画假低谷。


## 六、状态机与触发链

**状态流转（服务端强校验，终态不可回退、不能跳步）**

| 单据                 | 流转                                                                                             | 约束                                                         |
| -------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------ |
| 订单 `order`         | CREATED → POOLED → WAVED → PICKED → REVIEWED → OUTBOUND，可 CANCELLED                            | 只有 CREATED/POOLED 可取消                                   |
| 波次 `wave`          | CREATED → ASSIGNED → PICKING → PICKED → REVIEWING → REVIEWED → HANDOVERED → CLOSED，可 CANCELLED | 只有 CREATED/ASSIGNED 可改派、可取消；只有 HANDOVERED 可归档 |
| 拣货任务 `pick_task` | WAITING → PICKING → FINISHED（有缺货则 EXCEPTION）                                               | `start` 仅从 WAITING；`finish` 仅从 PICKING/EXCEPTION        |
| 复核单 `review`      | WAITING → PASS / DIFF                                                                            | 提交必须是 WAITING，重复提交返回业务失败                     |
| 交接单 `handover`    | CREATED → CONFIRMED / REJECTED                                                                   | 确认必须是 CREATED                                           |
| 缺货 `shortage`      | PENDING → HANDLED → CLOSED                                                                       | —                                                            |

**触发链（一次操作要连带改哪些表）**

```text
wave/generate   → INSERT wave + wave_order + pick_task + pick_item；order.status = WAVED
pick/start      → pick_task.status = PICKING；wave.status = PICKING
pick/finish     → pick_task.status = FINISHED/EXCEPTION；wave.status = PICKED；order.status = PICKED
review/submit   → review.status = PASS/DIFF；本波次复核单全部出结果 → wave.status = REVIEWED，order.status = REVIEWED
handover/confirm→ handover.status = CONFIRMED；wave.status = HANDOVERED；order.status = OUTBOUND
shortage/handle → shortage.status = HANDLED；wave.has_shortage = 1
```

**拣货明细合并规则**

- 同一波次内按 `locationCode + skuCode` 合并，`shouldQty` 累加，来源订单号记在 `relatedOrderNos`；
- 明细按 `location.pathSeq` 排序生成拣货路径（`pick_item.seq_no`），`pick_task.pathText` 存可读路径；
- 合并后 `pick_item` 条数 = 波次的 `locationCount` 量级，而不是订单行数。

## 七、维护方式

本文档与 `controller/*.java` 必须保持一致。改接口时按这张清单过一遍：

| 改动 | 需要同步的位置 |
| --- | --- |
| 新增 / 删除接口 | 「四、接口清单」对应模块的表格 + 顶部总览表的数量 |
| 改入参 | 该行的「入参」列 |
| 改返回结构 | 「五、关键数据结构」 |

核对方法（不需要额外工具）：数一下 Controller 里的注解，和文档表格的行数对一下。

```bash
grep -c "@GetMapping\|@PostMapping" backend/src/main/java/com/example/wms/controller/*.java
```

合计值应等于「四、接口清单」里所有表格的数据行数；再抽查几条路径是否逐字一致。
对不上就说明有接口漏改或漏写，以代码为准更新文档。
